# Spec Delta: eval-ci-gate

## Purpose

Lets CI rerun the ablation grid on a 50-question subset without model servers, by replaying recorded model traffic against a restored index snapshot, and fails the build when quality regresses.

## ADDED Requirements

### Requirement: Subset grid run
`uv run evals grid --subset ci` SHALL run the six grid configs on the 50 `ci_subset` questions, and `--no-generation --no-judge` SHALL disable generation in the sent pipeline and skip judging, writing results under `evals/runs/ci/` and never to `evals/results.md`.

#### Scenario: CI results isolated
- **WHEN** a subset grid run completes
- **THEN** new files exist under `evals/runs/ci/` and `evals/results.md` is unchanged

### Requirement: Regression thresholds
The harness SHALL generate `evals/thresholds/ci.yaml` from a real subset baseline run, setting each minimum to the baseline minus the tolerance (0.03 for nDCG@10 and recall@20 per config; 0.05 route accuracy and 0.10 SQL answer accuracy for `06-routing`), with zero allowed degraded responses, and SHALL record the baseline run id.

#### Scenario: Thresholds derived from a run
- **WHEN** `uv run evals thresholds --from runs/ci/<run_id>` runs
- **THEN** every threshold equals the baseline value from that run minus its tolerance, floored at 0

### Requirement: Gate exit codes
With `--gate <file>` the grid command SHALL exit 0 when every metric meets its threshold and no response is degraded, 1 when any metric is below its threshold, 2 when any response is degraded or a request fails, and 3 on setup errors, printing a table of metric, value and threshold per config.

#### Scenario: Regression fails
- **WHEN** a code change lowers `05-rerank` nDCG@10 below its threshold
- **THEN** the gate exits 1 and the printed table marks that row

#### Scenario: Cassette miss fails loudly
- **WHEN** replay mode receives a request with no recorded response
- **THEN** the gate exits 2 and prints that cassettes must be re-recorded with `make eval-record-ci`

### Requirement: Cassette recording
`uv run evals cassettes snapshot` SHALL capture the proxied model and reranker traffic of a recording run from wiremock into `evals/cassettes/ci/mappings/` with exact JSON body matching, replacing previous mappings, and write `evals/cassettes/ci/meta.json` with recording time, git sha, model digests, reranker model and revision, and the snapshot sha256.

#### Scenario: Replay reproduces the recording
- **WHEN** the subset grid is recorded and then replayed against the same snapshot
- **THEN** the replayed metrics equal the recorded metrics exactly and no response is degraded

### Requirement: Replay provenance
In `--replay` mode the runner SHALL take model digests from `evals/cassettes/ci/meta.json` instead of live Ollama and mark the run record as replayed.

#### Scenario: No live model server needed
- **WHEN** the gate runs in replay mode with Ollama stopped
- **THEN** it completes without contacting Ollama

### Requirement: Snapshot lock
The harness SHALL provide `evals/ci/snapshot.lock.json` describing the DB snapshot the cassettes were recorded against (release tag, asset name, sha256, pipeline fingerprint, document and chunk counts), generated by `uv run evals ci-lock --snapshot <path>`.

#### Scenario: Lock matches snapshot
- **WHEN** the snapshot file's sha256 is computed
- **THEN** it equals the lock file's `sha256`
