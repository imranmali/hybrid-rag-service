# Design: add-indexer

## Context

See proposal.md — Why. The schema, roles, environment variables, Ollama endpoints, author normalization and the digest lock are fixed by `add-platform-foundation/design.md` → "Cross-change contracts"; the relevant blocks are copied verbatim below and MUST NOT be changed here. The indexer runs on the host (`cd indexer && uv run indexer …`), connects as `rag_indexer` via `INDEXER_DATABASE_URL`, and calls host Ollama at `OLLAMA_HOST_URL`.

## Goals / Non-Goals

**Goals:**
- A corpus anyone can rebuild bit-for-bit from the committed manifest plus the cache.
- Chunks whose identity `(external_id, ordinal)` is stable, so eval gold labels survive re-indexing.
- Both contextual variants in one pass, so the ablation is a column switch.
- Zero model calls and zero writes on a no-op re-run.

**Non-Goals:**
- Speed beyond "a 200-paper ingest finishes in under an hour on the dev machine".
- Concurrency (the work is bounded by arXiv politeness and one local GPU; sequential is simpler and deterministic).

## Decisions

### D1. Package layout and dependencies
`indexer/pyproject.toml` (name `indexer`, `requires-python = ">=3.12,<3.13"`, script `indexer = "indexer.cli:app"`, ruff `extend = "../ruff.toml"`), `indexer/uv.lock`, source in `indexer/src/indexer/`:
`cli.py` (Typer), `config.py` (pydantic-settings; loads `../.env`), `arxiv/{api.py, html_fetch.py, cache.py, ratelimit.py, select.py}`, `parse/html_parser.py`, `chunk/{tokenizer.py, sentences.py, chunker.py}`, `enrich/{llm.py, context.py}`, `embed/ollama.py`, `store/writer.py`, `names.py`, `fingerprint.py`, `models_lock.py`, `bench.py`. Tests in `indexer/tests/` with synthetic fixtures in `indexer/tests/fixtures/`.
Runtime deps: `httpx`, `typer`, `pydantic>=2`, `pydantic-settings`, `python-dotenv`, `beautifulsoup4`, `lxml`, `tokenizers`, `huggingface_hub`, `psycopg[binary]>=3.2`, `pgvector`, `numpy`. Dev: `pytest`, `respx`, `ruff`, `testcontainers[postgres]`.

### D2. Corpus selection (`indexer select`)
- Pool: for each category in {cs.IR, cs.CL, cs.DB}, each year 2023–2026 and each quarter, query `https://export.arxiv.org/api/query?search_query=cat:<cat>+AND+submittedDate:[<YYYYMMDD>0000+TO+<YYYYMMDD>2359]&start=0&max_results=50&sortBy=submittedDate&sortOrder=ascending` (48 queries; 2026 windows end at the run date). Keep entries whose `arxiv:primary_category` equals the queried category.
- Prolific authors: count normalized author names in the pool; the 8 most frequent with ≥ 3 papers (ties by name) contribute up to 5 papers each (earliest first).
- Stratified fill: remaining slots split evenly over the 12 (category, year) strata; seeded `random.Random(42)` sample per stratum; a candidate is accepted only if its HTML exists and parses to ≥ 2000 tokens; shortfalls borrow from the same category's other years, then other categories.
- Output order: prolific-author papers, then round-robin across strata. Target 220 (so ~200 survive for `make index`). The manifest is committed; `ingest` never re-selects.

### D3. Context header = one LLM call per document + deterministic section path
BUILD_SPEC calls for a "doc-level situating sentence". Per-chunk LLM context (Anthropic-style contextual retrieval) would be ~6 000 calls to llama3.1:8b (hours locally); one call per document (~200) plus the deterministic section path gives each chunk a chunk-specific header at ~3 % of the cost. Prompt version `ctx-v1`:
- system: `You write one sentence that situates a research paper for a search index.`
- user: `Title: …\nCategories: …\nAbstract: …\nSection headings: <comma-separated, truncated to 1500 tokens total>\n\nWrite ONE sentence of at most 50 words stating the paper's problem, approach and domain. Output only the sentence.`
- options per contract C3 (`num_predict` 96, no `format`). Post-process: strip quotes, keep the first sentence, truncate to 50 words.
- `context_header = f"Paper: {title} ({primary_category}, {published_on.year}). Section: {section_path}. {context_summary}"`.

### D4. Contextual-variant storage = two columns (matches foundation D1)
`embedding = embed(content)`, `embedding_ctx = embed(context_header + "\n\n" + content)`; `tsv`/`tsv_ctx` are generated by Postgres. Both computed in the same pass. See foundation design D1 for the rationale (stable gold ids, single chunk set).

### D5. Chunking: 384 / 64, section-bounded, sentence-aligned
- Tokenizer: `tokenizers.Tokenizer.from_pretrained("BAAI/bge-m3")`, counting without special tokens (same family the reranker uses, so 384 + header (~80) + query (~25) stays under the reranker's 512-token pair limit).
- Sentence splitter: regex on `[.!?]` followed by whitespace + uppercase/digit/`(`, with an abbreviation list (`e.g.`, `i.e.`, `et al.`, `Fig.`, `Figs.`, `Eq.`, `Sec.`, `Tab.`, `vs.`, `cf.`, `approx.`, `No.`) and no split inside `$…$`.
- Pack sentences greedily to ≤ 384 tokens; the next chunk starts with trailing sentences of the previous chunk whose total ≤ 64 tokens; a tail < 64 tokens merges into the previous chunk of the same section (so max 448); a sentence > 384 tokens is split into 384-token windows with 64-token overlap (decode token spans).
- Abstract is section `Abstract`. Sections with < 20 tokens of text are skipped. Ordinals 0..n-1 across the document.
- Why 384: a 512-token chunk + header + query would be truncated by the reranker; 256 fragments method descriptions in these papers. The choice is recorded in ADR 0005.

### D6. HTML parsing (parser version `html-v1`)
LaTeXML markup: document `article.ltx_document`; title `h1.ltx_title_document`; abstract `div.ltx_abstract`; sections `section.ltx_section|ltx_subsection|ltx_subsubsection|ltx_appendix` with headings `.ltx_title` (tag number from `.ltx_tag`); text from `div.ltx_para` paragraphs, list items, `figcaption` (prefixed `Figure: ` / `Table: `), `table.ltx_tabular` rows joined with ` | ` (max 40 rows). `math[alttext]` → `$<alttext>$`. Removed: `section.ltx_bibliography`, `.ltx_note` (footnotes), `nav`, `header`, `footer`, `.ltx_page_footer`, `.ltx_ERROR`, sections titled Acknowledg(e)ment(s). Text normalized to NFC with collapsed whitespace. A page without `article.ltx_document` counts as "no HTML".

### D7. Fetching, rate limiting, cache
- One process-wide limiter: `min_interval = 3.0 s` measured from the end of the previous network request (cache hits are free). Retries on 429/500/502/503/504/connect errors: waits 5, 15, 45 s (`max(wait, Retry-After)`), then fail that paper.
- User-Agent: `hybrid-rag-indexer/0.1 (research portfolio project; mailto:<ARXIV_CONTACT>)`, omitting the mailto when unset.
- Cache: `data/cache/arxiv/api/<sha1(url)>.xml`, `data/cache/arxiv/html/<id>v<n>.html`, negative `…/<id>v<n>.missing`. Writes are atomic (temp file + rename). Path resolved as `<repo root>/data/cache` (repo root = parent of `indexer/`).

### D8. Hashes, fingerprint, identity
- `documents.id = uuid5(NAMESPACE_URL, "arxiv:" + external_id)`.
- `content_hash = sha256(f"{arxiv_version}\n{title}\n{abstract}\n{raw_text}")`.
- `pipeline_fingerprint = sha256(json.dumps({...}, sort_keys=True))` over `chunk_size_tokens=384`, `chunk_overlap_tokens=64`, `min_chunk_tokens=64`, `tokenizer="BAAI/bge-m3"`, `header_prompt_version="ctx-v1"`, `parser_version="html-v1"`, `embedding_model`, `embedding_model_digest`, `llm_model`, `llm_model_digest` (Anthropic: `llm_model="anthropic:<ANTHROPIC_MODEL>"`, digest = the model id).
- `content_sha256 = sha256(content.encode("utf-8"))`.

### D9. Write path
Per document, one transaction: upsert `documents` (on conflict `external_id` do update all columns, `ingested_at = now()`), `delete from chunks where document_id = …`, `delete from paper_authors/paper_categories where document_id = …`, upsert authors (`on conflict (name_normalized) do nothing`, then select ids), insert links, insert chunks with `executemany` (pgvector adapter). After the run: delete orphan authors, upsert all `index_metadata` keys (foundation C1), `ANALYZE documents, chunks, authors, paper_authors, paper_categories` (allowed by the `MAINTAIN` grant). Skip rule: stored `content_hash` and `pipeline_fingerprint` both equal → no LLM/embedding calls, no writes. `--force` ignores the skip rule; `--prune` deletes documents not among the first `--limit` manifest entries.

### D10. Exit codes
0 = success with failures ≤ 5 % of processed documents; 1 = more failures; 2 = usage/config error (missing manifest, bad DSN); 3 = model digest drift (contract C3). Failures are listed (id + reason) before the summary line.

### D11. Index benchmark (`indexer bench-index`)
As `rag_indexer` (TEMP privilege): `create temp table bench_vec as select c.id, c.embedding, d.primary_category, extract(year from d.published_on)::int as year from chunks c join documents d on d.id = c.document_id`; time `create index … using hnsw (embedding vector_cosine_ops) with (m = 16, ef_construction = 64)`; 200 seeded query chunks (self excluded via `where id <> :qid`); exact top-10 with `set local enable_indexscan = off`; HNSW top-10 at `ef_search` 40/100/250; drop, build IVFFlat (`lists = round(sqrt(n))`), probes 1/5/10. Filtered section: for each primary category and each year, HNSW + `WHERE` (pgvector `hnsw.iterative_scan = off`) vs exact filtered top-10, with selectivity = matching rows / n. Writes `indexer/bench/index_bench.json` and a markdown table `indexer/bench/index_bench.md` (both committed; numbers only from real runs).

`infra/migrations/V1__schema.sql`:

```sql
create extension if not exists vector;
create extension if not exists pg_trgm;

-- One row per arXiv paper (the version that was ingested).
create table documents (
  id                   uuid primary key,          -- uuid5(NAMESPACE_URL, 'arxiv:' || external_id), computed by the indexer
  external_id          text not null unique,      -- arXiv id WITHOUT version, e.g. '2403.01234'
  arxiv_version        int  not null,             -- ingested version number, e.g. 2
  title                text not null,
  abstract             text not null,
  primary_category     text not null,             -- e.g. 'cs.IR'
  published_on         date not null,             -- arXiv <published> (v1 submission date)
  updated_on           date not null,             -- arXiv <updated>
  source_url           text not null,             -- 'https://arxiv.org/html/' || external_id || 'v' || arxiv_version
  raw_text             text not null,             -- normalized full text, sections joined, references removed
  context_summary      text not null,             -- LLM doc-level situating sentence (<= 50 words)
  content_hash         text not null,             -- sha256 hex, see indexer design
  pipeline_fingerprint text not null,             -- sha256 hex of indexing config, see indexer design
  ingested_at          timestamptz not null default now()
);
create index documents_category_date on documents (primary_category, published_on desc);
create index documents_published_on  on documents (published_on);

create table authors (
  id              bigserial primary key,
  name            text not null,                  -- display form as first seen on arXiv
  name_normalized text not null unique            -- see contract C4 (author-name normalization)
);
create index authors_name_trgm on authors using gin (name_normalized gin_trgm_ops);

create table paper_authors (
  document_id uuid   not null references documents(id) on delete cascade,
  author_id   bigint not null references authors(id),
  position    int    not null,                    -- 1-based author order
  primary key (document_id, position),
  unique (document_id, author_id)
);
create index paper_authors_author on paper_authors (author_id);

create table paper_categories (
  document_id uuid    not null references documents(id) on delete cascade,
  category    text    not null,                   -- e.g. 'cs.IR', 'cs.LG'
  is_primary  boolean not null,
  primary key (document_id, category)
);
create index paper_categories_category on paper_categories (category);

create table chunks (
  id             bigserial primary key,
  document_id    uuid not null references documents(id) on delete cascade,
  ordinal        int  not null,                   -- 0-based within the document; stable for identical text + chunker config
  section_path   text not null,                   -- e.g. '3 Method > 3.2 Index construction'
  content        text not null,                   -- chunk body (no header)
  context_header text not null,                   -- 'Paper: <title> (<primary_category>, <year>). Section: <section_path>. <context_summary>'
  token_count    int  not null,                   -- bge-m3 tokenizer count of content
  content_sha256 text not null,                   -- sha256 hex of content (UTF-8)
  embedding      vector(1024) not null,           -- bge-m3(content)
  embedding_ctx  vector(1024) not null,           -- bge-m3(context_header || E'\n\n' || content)
  tsv            tsvector generated always as (to_tsvector('english', content)) stored,
  tsv_ctx        tsvector generated always as (to_tsvector('english', context_header || ' ' || content)) stored,
  unique (document_id, ordinal)
);
create index chunks_embedding_hnsw     on chunks using hnsw (embedding     vector_cosine_ops) with (m = 16, ef_construction = 64);
create index chunks_embedding_ctx_hnsw on chunks using hnsw (embedding_ctx vector_cosine_ops) with (m = 16, ef_construction = 64);
create index chunks_tsv_gin            on chunks using gin (tsv);
create index chunks_tsv_ctx_gin        on chunks using gin (tsv_ctx);
create index chunks_document           on chunks (document_id);

-- Written by the indexer at the end of every ingest; read by the service (/v1/info) and evals.
create table index_metadata (
  key        text primary key,
  value      text not null,
  updated_at timestamptz not null default now()
);
```

<!-- CONTRACT:ollama -->
Models: embeddings `bge-m3` (1024 dims, L2-normalized by Ollama), LLM `llama3.1:8b`. Base URL: `OLLAMA_HOST_URL` (host processes) or `OLLAMA_CONTAINER_URL` / `RAG_OLLAMA_URL` (containers).

Embeddings — `POST {base}/api/embed`
```json
{"model": "bge-m3", "input": ["text 1", "text 2"], "truncate": true, "keep_alive": "30m"}
```
→ `200 {"model": "bge-m3", "embeddings": [[1024 floats], [1024 floats]], "prompt_eval_count": 37}`.
Indexer batches ≤ 32 inputs per call; the service always sends exactly one input. No query/document prefix is used with bge-m3.

Chat — `POST {base}/api/chat`
```json
{
  "model": "llama3.1:8b",
  "messages": [{"role": "system", "content": "…"}, {"role": "user", "content": "…"}],
  "stream": false,
  "format": "json",
  "keep_alive": "30m",
  "options": {"temperature": 0, "seed": 42, "num_ctx": 8192, "num_predict": 384}
}
```
→ `200 {"message": {"role": "assistant", "content": "…"}, "prompt_eval_count": 812, "eval_count": 96, "done": true}`.
`format: "json"` is sent only for structured outputs (routing, SQL generation, judge, dataset generation); omitted for free-text answers and context summaries. `num_predict` per use: route 32, SQL generation 256, answer 384, context summary 96, judge 128, dataset generation 512. `temperature` is always 0 and `seed` is always `LLM_SEED` (42).

Model inventory — `GET {base}/api/tags` → `{"models": [{"name": "bge-m3:latest", "digest": "<64-hex>", …}, …]}`. A configured name without a tag matches `<name>:latest`.

Digest pinning — `infra/models.lock.json` (generated by `make models-lock`, committed):
```json
{
  "generated_at": "2026-10-10T00:00:00Z",
  "ollama": {
    "bge-m3": {"digest": "<64-hex from /api/tags>"},
    "llama3.1:8b": {"digest": "<64-hex from /api/tags>"}
  },
  "reranker": {"model": "BAAI/bge-reranker-v2-m3", "revision": "<40-hex Hugging Face commit sha>"}
}
```
Enforcement: the indexer and the eval runner FAIL (exit code 3) if a live digest differs from the lock, unless `--allow-model-drift` is passed (recorded in their output). The service never fails on drift; it logs an ERROR and reports `embedding_digest_matches_index` in `GET /v1/info`.

Anthropic provider (optional, all three Python/Kotlin LLM clients): used only when `LLM_PROVIDER=anthropic`; then `ANTHROPIC_API_KEY` and `ANTHROPIC_MODEL` are required (startup error otherwise). Embeddings always use Ollama `bge-m3`. Nothing ever requires a key.

## Risks / Trade-offs

- [arXiv HTML missing for many 2023 papers] → selection checks HTML before accepting and backfills from other years; the manifest records what was chosen.
- [LaTeXML markup varies] → parser tolerates missing classes, counts tokens, rejects pages under 2000 tokens; fixture tests cover nested sections, math, tables, bibliography removal.
- [Author homonyms merged by normalized name] → accepted; arXiv has no author ids. Documented in the dataset card and README as a known limitation for aggregate questions.
- [llama3.1:8b output not perfectly deterministic across hardware] → temperature 0 + seed; summaries are stored, so re-runs skip them unless the fingerprint changes.
- [Tokenizer download on first run] → `huggingface_hub` caches it; `indexer status` warms it.
- [HNSW incremental inserts slower than bulk build] → ~6k rows, acceptable; build time is measured separately by `bench-index`.

## Migration Plan

`make index` (= `uv run indexer ingest --limit 200`). Re-index after a config change is automatic (fingerprint). Rollback: `make clean && make up && make index`.
